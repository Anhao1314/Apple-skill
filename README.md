# Apple Product Design

### 像苹果一样定义产品，而不是堆砌功能。

一个去人格化的 Agent Skill。
不扮演乔布斯，不规定像素，只回答一个问题——

**什么该留下，什么该删掉。**

## 这是什么

苹果的强大不在功能数量，而在取舍的勇气。

但当 AI 评审产品时，它最擅长输出的，恰恰是"要极简、重体验、以用户为中心"这类正确的废话。

这个 skill 把苹果四十余年的产品决策方法，拆成一套可以逐步执行、可以逐项判定、必须给出替代方案的流程。它不告诉你"要简洁"，它会逐个功能问你：**删掉它，80% 的用户会受影响吗？**

## 它不是什么

市面上已有两类苹果相关 skill，本 skill 刻意站在它们留下的空位上。

| | HIG 类 skill | 人物视角 skill | 本 skill |
| --- | --- | --- | --- |
| 管什么 | 字号、配色、动效、组件 | 模仿乔布斯的口吻分析 | 产品定义、功能取舍、体验链条 |
| 产出 | 合规的界面 | 一段人物对话 | 评审报告、功能取舍表、产品定义卡 |
| 适用对象 | 苹果平台界面 | 角色扮演与灵感 | 任意软硬件、互联网、AI 产品 |

## 工作方式

三种模式，按你手上的材料自动路由。

**评审。** 给它一份 PRD、功能清单或产品方案。它走完七步审计——本质定义、功能减法、体验倒推、端到端链条、品类定位、工艺情感与决策机制——然后输出分级问题，每条都带着苹果式替代方案和第一步动作。

**定义。** 从一个模糊想法开始。它带你找到既有品类里"烂到想摔东西"的体验，写出 "1000 songs in your pocket" 式的一句话定义，划定 v1 只做什么、以及明确不做什么。

**问答。** 回答"苹果会怎么做这类产品"。并严格区分：哪些是苹果官方史实，哪些只是方法论推断。

### 一条主线贯穿全部

> 从用户要完成的事情倒推，敢于对一千个好主意说不，端到端地为完整体验负责，直到把复杂收敛成一句话能说清的本质。

## 十条原则

每条原则都配有出处原文、可回答的检查问题、AI 最容易给出的平庸答案、正反案例，以及——它的**局限与代价**。原则从不被当成教条。

1. **从本质出发，一句话定义** —— 不用参数和形态，说清用户要完成什么。
2. **聚焦就是说不** —— 聚焦不是决定做什么，是对上百个好主意摇头。
3. **体验倒推技术** —— 从理想体验反推技术，而不是拿着技术找场景。
4. **端到端负责** —— 体验链条断在别人手里，账都算在你头上。
5. **重定义品类，而非发明品类** —— iPod 不是第一台 MP3，iPhone 不是第一台手机。
6. **深层简洁，而非表层极简** —— 复杂度不会消失，你不消化它，就转嫁给用户。
7. **工艺细节建立信任** —— 出错的时候、没人看见的地方，才是考场。
8. **技术与人文交汇** —— 愉悦是做对一切之后的结果，不是贴上去的彩带。
9. **原型先于论证** —— 分歧靠做出来的东西裁决，不靠第三场会议。
10. **小团队与品味决策机制** —— 委员会投票，平均不出卓越。

案例库覆盖 iMac、iPod、iPhone、MacBook Air、iPad、Apple Store、AirPods、Apple Watch，以及 HomePod 一代、Newton、Vision Pro 这些**苹果自己的教训**。

## 评审长什么样

输入一份功能不断膨胀的产品方案，你会得到这样的东西：

```text
一句话总判断：这个产品没有主线——它在同时解决七个问题，
于是没有一个被解决好。

功能取舍表
├─ 功能 A（核心路径）        保留强化
├─ 功能 B（A 的一个场景）    合并进 A
├─ 功能 C（不足 5% 用户）    下沉二级
└─ 功能 D（竞品有所以我也要） 删除

致命问题 1：定义是参数堆砌，不是用户任务
  违背原则：1 从本质出发
  替代方案：改写成"谁、在什么场景、完成什么"，一句话，无参数
  第一步：删掉介绍页全部形容词，只留一个具体使用画面
```

批评必须具体到功能，每条意见必须能被执行。做不到，就重写。

## 安装

兼容 Agent Skills 协议的任意 runtime（Claude Code、Codex、Cursor、Gemini CLI 等 50+ 环境）。

**方式一：通用安装器（推荐）**

```bash
npx skills add Anhao1314/Apple-skill
```

**方式二：手动安装**

```bash
git clone https://github.com/Anhao1314/Apple-skill.git
```

将整个目录放入对应 runtime 的 skills 发现目录，例如：

| Runtime | 路径 |
| --- | --- |
| Claude Code | `~/.claude/skills/` |
| Codex CLI | `~/.codex/skills/` |
| Cursor | `~/.cursor/skills/` |
| 其他兼容 runtime | 其官方文档指定的 skills 目录 |

**方式三：直接使用**

把 `SKILL.md` 的内容粘贴进任意对话——它本质上就是一份带 YAML 头信息的 Markdown。

## 使用

```text
用苹果产品方法论帮我评审这份 PRD
像苹果一样帮我定义这个产品，现在只有一个模糊方向
这十几个功能，帮我判断该砍哪些
苹果会怎么进入这个品类？
```

## 信源纪律

只采信三类来源：苹果官方一手材料（Keynote、WWDC、公开信）、授权传记与共事者记录、明确标注为分析的外界研究。无出处的"乔布斯语录"和营销鸡汤一律排除；涉及 2011 年之后的苹果，先联网核实再下判断。
