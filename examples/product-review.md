# 产品评审示例

材料和产品均为虚构。输出由维护者手写，仅示范格式与取舍，不是 Agent 实测记录。安装时保留完整目录；无需额外文件。

## 完整输入（复制调用）

```text
请用 apple-product-design 做轻量产品评审。
产品：虚构的「稿件回声」，自由职业设计师的客户反馈网页。
核心任务：客户无需注册，在图片上标注意见；设计师集中处理。
功能：匿名分享链接、图片标注、反馈状态、团队聊天、AI 广告文案。
资源：独立开发，首版两周，仅网页，不接外部模型服务。
现有材料：以上功能清单；没有访谈、访问量或权限设计。
请输出总判断、逐功能取舍、下一步，标明假设；不要写代码。
```

## 示范输出

总判断：围绕图片反馈形成最小闭环。两周只是你的排期约束，不是可行性承诺。

| 功能 | 取舍 | 理由 |
| --- | --- | --- |
| 匿名链接 | 保留强化 | 满足客户无需注册；应可撤回，避免公开永久暴露 |
| 图片标注 | 保留 | 主任务的输入方式 |
| 反馈状态 | 保留最小版 | 让设计师知道哪些已处理，不扩展审批系统 |
| 团队聊天 | 暂缓 | 尚无多人协作证据，可沿用现有沟通渠道 |
| AI 广告文案 | 删除首版 | 偏离任务；外部模型服务违反约束 |

假设：设计师端可认证；匿名仅指客户。没有材料证明匿名链接的敏感性要求。
关键问题：是否包含不能通过链接外传的保密稿？它会改变权限方案。
下一步：先用虚构稿走通分享、标注、处理和撤回；评估开发量后再确认排期。

入口：[SKILL.md](../SKILL.md)。完整评审可按 [模板](../assets/review-template.md)展开；本例不要求加载所有参考资料。
