# 产品定义示例

材料和产品均为虚构。输出由维护者手写，仅示范格式与取舍，不是 Agent 实测记录。安装时保留完整目录；无需额外文件。

## 完整输入（复制调用）

```text
请用 apple-product-design 定义一个 MVP。
想法：虚构的「约时小册」，供独立摄影师处理预约询问。
当前替代：聊天中反复询问档期、地点和需求，然后手工记入日历。
目标：减少来回问答，但不自动确认预约。
约束：一人开发，一周试作；不接支付，不改客户现有聊天工具。
材料：只有创始人观察，没有访谈和需求比例。请给定义、v1、不做项和验证计划。
```

## 示范输出

一句话定义：让客户一次提交拍摄时间与需求，由摄影师手动确认预约。

假设：主要断点是收集信息，而非客户获取或档期冲突；尚无访谈证明。
理想路径：聊天发送表单链接 → 客户填写候选时间和需求 → 摄影师查看 → 回到聊天确认 → 手工登记日历。
v1：可分享的需求表、提交记录、摄影师标记处理状态。能力数量只是当前任务的结果，不是固定上限。
不做：支付、自动确认、聊天替代、实时日历同步。
端到端断点：表单提交不等于预约成功；成功页明确提示等待摄影师在聊天中确认，并提供原联系渠道。
关键问题：客户是否必须看到可预约时段？若需要，v1 必须加入档期展示或明确不可用时间。
下一步：先用手工表单原型，请少量目标用户尝试；记录补问信息与误以为已确认的情况，再决定是否实现。没有实测结果，不能声称已减少问答。

入口：[SKILL.md](../SKILL.md)。完整评审可按 [模板](../assets/review-template.md)展开；本例不要求加载所有参考资料。
